# v0.9.0: comics and doodles from a few lines of text

## TL;DR

`c2m excalidraw` reads a new compact text format, `.c2m` (or `.sketch`). An agent writes panels, stick figures, speech bubbles, boxes and arrows in about 20 lines; the tool lays everything out and draws it in the house style, then runs the lint. Same outputs as before: share link, PNG, paste block.

## Why

A 3-panel explainer comic needed about 7,600 characters of element JSON with hand-computed coordinates, and agents spent most of their effort on arithmetic instead of the story. The same comic is now 848 characters, and the layout rules (bubbles above speakers, labels beside arrows, panels on a grid, text that prints at about 14 pt) live in the tool instead of in each prompt.

## Highlights

| What | Detail |
|---|---|
| Input | `c2m excalidraw comic.c2m`, auto-detected by extension; `--png`, `--strict`, `--no-upload`, `c2m lint` all work |
| Statements | `strip`, `title`, `panel`, `grid`, `id: figure`, `id: box`, `a -> b`, `id says`, `id thinks`, `stat`, `note` |
| Colour | three markers only: `accent` (blue), `bad` (red), `good` (green); everything else is black on white |
| Errors | `file:line`, the offending line and a `fix:` hint |
| Lint | the sample comic produces zero findings, including the colour budget and the font-size check |

## Example

```text
strip 2 cols
panel "The ask" note "Two words, three meanings."
  client: figure sad @left "Client"
  me: figure @right "You"
  client says "I need the\nsales dashboard\nLIVE." accent
  me says "...define\n'live'?"
```

## Upgrade notes

Nothing changes for JSON, Mermaid or doodle input. Standard input (`-`) still reads JSON only. `c2m excalidraw --help` has a new SKETCH section with the full grammar.
